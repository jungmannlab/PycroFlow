What PycroFlow is

PycroFlow is a Python framework that coordinates the three subsystems of an automated fluorescence-microscopy experiment so they run as one timed, abortable sequence:

  • Fluid handling — Hamilton MVP rotary valves and PSD syringe pumps, driven over serial, exchange imager/buffer solutions through the sample chamber.
  • Image acquisition — Micro-Manager (via pycromanager), including Perfect Focus System (PFS) monitoring.
  • Illumination — laser power and wavelength control via the monet sibling project.

It targets Windows 10 with hardware serial communication and runs on Python 3.10+. It is used in production for Exchange-PAINT, MERPAINT, and related multiplexed DNA-PAINT experiments.

What it can do

Experiment types are dispatched through a registry in the protocol builder:

TypeDescription
ExchangeExchange-PAINT: sequentially image a series of imagers, washing between rounds.
MERPAINTAdapter/eraser hybridization rounds with imaging in between.
SPH-RESIResolution-enhancement rounds with adapter labelling and blocking per target.
FlushTestA diagnostic sequence for testing fluid delivery.

Experiments support pause / resume / abort and survive focus loss (PFS monitoring can pause and rewind the protocol).

How it is built

Orchestration

A ProtocolOrchestrator runs one daemon thread per subsystem (fluid, imaging, illumination). The threads stay in step using a signal / wait-for-signal protocol: one subsystem emits a named signal (e.g. "fluid round 1 done") and another waits for it before proceeding. Waiting is event-backed (no busy polling) with a hard timeout.

Protocols

A high-level experiment description is transformed by the ProtocolBuilder into per-subsystem lists of typed steps (each a dict with a $type field, e.g. inject, acquire, set power, signal, wait for signal). Steps are validated against a schema and serialized to YAML, which can be inspected and hand-edited before a run.

Hardware

SubsystemHardware / driver
FluidHamilton MVP valves + PSD syringe pumps, in-house serial driver (pyHamilton); topology defined in YAML configs.
ImagingMicro-Manager Core/Studio via pycromanager; PFS focus monitoring.
Illuminationmonet (laser power/wavelength, shutter, beam path).
Spill sensorOptional Arduino-based wet/dry sensor that can pause a run on a detected spill.

Frontends

  • pycroflow — an interactive command-line interface (the workhorse in the lab; full control over fluid, imaging and illumination).
  • pycroflow-gui — a tabbed Qt GUI (PyQt6), launched with pycroflow-gui or python -m PycroFlow.gui.

Both frontends sit on the same frontend-agnostic services layer (experiment lifecycle and manual hardware control), so neither reaches into orchestration internals.

The Qt GUI tabs

A toolbar (Load protocol / Start / Pause / Abort) sits above four tabs:

TabWhat it shows / does
ExperimentThe main control surface: load a protocol, Start / Pause / Resume / Abort, a live experiment-state label, the fluid protocol step list, and a log pane.
FluidFluid-system status and manual fluid control: Fill tubings, Clean tubings (using config defaults), and Stop all moves.
ImagingRead-only imaging status: connection, PFS status, last acquisition.
MonetEmbeds monet's own laser-control window in-process, so PycroFlow imaging and monet share one Micro-Manager connection (no two-process conflict).

Monet tab. PycroFlow's GUI and monet are both on PyQt6, so monet's window embeds directly in the Monet tab. If monet isn't installed, the tab shows a placeholder instead of failing.

The GUI currently exposes a subset of the CLI. For parameterised cleaning (specific reservoirs/volumes), manual inject/deliver/set_valves, or direct laser/power commands, use the pycroflow CLI.

Installation
