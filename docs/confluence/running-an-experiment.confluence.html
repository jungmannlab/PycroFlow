This workflow combines the lab standard operating procedures with the current PycroFlow command-line interface. Buffer recipes, volumes, reservoir numbers and COM ports are lab- and setup-specific — the values below are typical examples; adjust them to your rig.

Overview

A run is driven from a single pycroflow command-line session that orchestrates fluid exchange, acquisition, and illumination. The high-level shape of a session is:

  1. Prepare buffers and passivate tubes / tubings.
  2. Edit start_experiment.py for this experiment.
  3. Launch PycroFlow, fill the tubings, load imagers.
  4. Mount the sample and needles, find positions.
  5. start_protocol and let it run.
  6. Clean the tubings and shut down.

1. Before you start: passivate tubes

Passivation reduces non-specific binding of imagers to the reservoir tubes.

  • Use DNA low-bind tubes.
  • DyBE DNA-PAINT flavour only: first fill with ~1 ml antibody-incubation buffer without salmon sperm DNA; invert 6×; incubate ≥ 30 min; remove liquid. (Skip this step for other DNA-PAINT flavours.)
  • Fill with ~1 ml imaging buffer + 0.1% BSA + 0.1% Tween-20; invert 6×; remove liquid.
  • Prepare ~1 ml of each imaging mix (one passivated tube per imaging round).

2. Power up and prepare software

  1. Switch on the fluidics power supply (pumps) and the microscope.
  2. Start Micro-Manager and configure it (and monet) exactly as for a manual experiment.
  3. Into the folder where data will be stored, copy execute pycroflow (the launcher shortcut) and start_experiment.py from a previous run.

3. Configure start_experiment.py

Open start_experiment.py and adjust the settings block at the top. The most commonly changed parameters:

ParameterMeaning
experiment_nameBase name for the output folder and generated protocol file.
reservoir_namesMap of tubing/connector position → solution name. By lab convention reservoir 6 is the wash buffer — do not repurpose it.
initial_targetName of the imager already present in the sample (no exchange needed for round 1), or None.
target_sequenceOrdered list of targets to image. Omit the initial_target. All names must appear in reservoir_names.
exposure_timeCamera exposure in ms.
n_framesFrames per acquisition.
use_mm_positionsTrue to acquire at all Micro-Manager position-list positions.
laser, sample_powerIllumination line (nm) and sample power (mW).
wash_volume, imager_volume, volume_reduction_for_xchgFluidic volumes (µl). The sample chamber must hold at least volume_reduction_for_xchg above the output needle.

Save the file when done. The connection topology and fluidic parameters lower in the file rarely change between runs on the same rig.

4. Launch PycroFlow and prime the tubings

Start the CLI by double-clicking execute pycroflow (or running pycroflow). Loading the interface auto-generates a timestamped YAML protocol file (named with the experiment name and creation time).

Passivate the tubings

  1. Connect tubes of incubation/passivation buffer to the reservoirs you will use.
  2. Run fill_tubings twice to pull buffer through and passivate the lines; incubate ~15 min.
  3. Remove the passivation tubes and run fill_tubings again to empty the lines.

Load imagers

  1. Insert the imager tubes. Each imager's position must match its reservoir_names entry in start_experiment.py.
  2. If an imager is already in the sample, set it as initial_target (then you don't connect its tube).
  3. Run fill_tubings once more to fill the lines with the correct imager and buffer.
  4. Run start_orchestration to start the subsystem threads.

5. (Optional) Adjust acquisition per target

To change settings for specific rounds without re-running start_experiment.py:

  1. Open the auto-generated YAML protocol (experiment name + date/time in the file name).
  2. Steps are grouped by subsystem (fluid, img, illu). To change frames for TargetC, find the img entry with $type: acquire and a message like "imaging round N - TargetC" and edit frames. To change power, find the illu entry with $type: set power for that target.
  3. Save the YAML.
  4. In the CLI, run load_protocol <filename>.yaml.

6. Mount the sample and start

  1. Connect the input needle (blue) and output needle (red) to the sample. Immerse the blue needle deeper than the red one in the liquid.
  2. Put the sample on the scope (e.g. a single-channel slide with ~300 µl of the first imaging mix).
  3. find positions in Micro-Manager if using use_mm_positions.
  4. Run start_protocol.
  5. Monitor the run. When the CLI reports that the last protocol entry of all subsystems has been performed, run help to return to a normal prompt.

While running you can pause_protocol, resume_protocol, or abort_protocol. The Perfect Focus System is monitored automatically and can pause/rewind the protocol if focus is lost.

7. Clean the tubings

  1. Recover any imagers you still need (otherwise they go to waste).
  2. Exchange the sample buffer (e.g. for 20% EtOH) and put both needles into the same waste/falcon tube so the output can suck up what the input dispenses.
  3. Run help clean_tubings to review parameters, then clean. The current parameters are:
ParameterMeaning
extra_volVolume (µl) on top of the tubing volume to push through each path (default 100). May be given positionally as the first argument.
cleaning_reservoirsReservoir ID, or comma-separated list, of the cleaning-liquid tanks, in order. Defaults to the config.
velocityPump velocity in µl/min (default: clean_velocity / max_velocity from config).
modechain (default; shuttle one fill volume through all reservoirs then out the needle) or individual (fresh liquid per reservoir; more thorough).
max_reservoir_volIf set, each reservoir is first emptied (up to this volume) through the needle before cleaning.
text

During cleaning: all reservoir tubes are emptied (if max_reservoir_vol is set), then filled with cleaning liquid, pushed out the blue input needle, and drawn via the red output needle into waste.

Older lab notes reference reservoir_vol=... and empty_finally=...; those were renamed/removed. Use max_reservoir_vol and mode as above, and run help clean_tubings for the authoritative list on your installed version.

8. Shut down

  1. exit the CLI.
  2. (If cleaning in stages) relaunch execute pycroflow, start_orchestration, and repeat clean_tubings with the next cleaning liquid (e.g. H₂O + 0.02% NaN₃, then Ethanol), then exit again.
  3. Switch off all lasers (in monet: laser all off).
  4. Switch off the pump power supply and the microscope.
  5. Everything else is the same as for a normal microscopy experiment.

Alternative: driving the run from the Qt GUI

Instead of the CLI, you can use the tabbed Qt GUI. Launch it with pycroflow-gui (or python -m PycroFlow.gui). The physical preparation — passivation, connecting tubes, mounting the sample and needles, buffer exchange — is identical to the CLI procedure above; only the software control surface differs.

TabUse during a run
ExperimentLoad the protocol, then Start / Pause / Resume / Abort. The state label and log pane show progress; the step list shows the fluid protocol.
FluidFill tubings for priming/passivation, Stop all moves as an emergency stop, and Clean tubings (with the configuration's default parameters).
ImagingCheck connection / PFS status (read-only).
MonetLaser control, embedded in-process (monet and PycroFlow share one Micro-Manager connection).

A typical GUI run: Fill tubings (Fluid tab) to prime → load the protocol and Start (Experiment tab) → monitor in the log → Clean tubings (Fluid tab) when finished.

The GUI exposes a subset of the CLI. For parameterised cleaning (specific cleaning_reservoirs / extra_vol / max_reservoir_vol), manual inject / deliver / set_valves, or direct laser / power commands, use the pycroflow CLI. The GUI's Clean tubings button uses the configuration defaults.

Monet tab. Both PycroFlow's GUI and monet are on PyQt6, so monet's laser-control window embeds directly in the Monet tab and shares PycroFlow's Micro-Manager connection. If monet isn't installed, the tab shows a placeholder instead of failing.

CLI command quick reference

CommandWhat it does
fill_tubingsFill the tubings from their reservoirs (used for priming and passivation).
start_orchestrationStart the per-subsystem threads (ready to run a protocol).
load_protocol <file>.yamlLoad a (possibly hand-edited) protocol YAML.
start_protocolRun the loaded protocol. Optional start entries, e.g. start_protocol fluid: 5, img: 2.
pause_protocol / resume_protocol / abort_protocolPause, resume, or abort the running protocol.
get_protocol_iter / set_protocol_iterInspect or set the current step per subsystem.
is_protocol_doneReport whether all subsystems finished.
deliver / inject / set_valves / pumpManual fluid operations.
laser / powerManual illumination control.
clean_tubingsClean all tubings (see parameters above).
help / help <command>List commands / show detailed help for one.
exitCleanly stop orchestration and leave the CLI.
